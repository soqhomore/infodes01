# 개복치 휴식 시뮬레이터 — 본 계획

2026-10-12 갱신 · 기존 `plan-v2.md` 경로 유지

## 프로젝트와 설계 원칙

정보디자인 A1 포스터 「내 휴식은 충분히 가치 있었을까?」를 개복치와 함께하는 브라우저 하루 여행으로 옮긴다. 플레이어는 내 상태에 맞게 장소와 머무는 방식을 선택하고 마지막에 자기 기록을 돌아본다. 제출물은 배포 URL과 사람이 작성하는 저널이며, 마감은 2026-10-12(월) 23:59다.

**전달할 메시지: 휴식의 가치는 금액이 아니라 주도성과 시야의 넓이가 결정한다.** 플레이에서는 몸·마음·시간 사이의 선택으로 이를 경험하게 한다. 기록은 이 메시지를 규칙으로 번역한 결과이며 실제 휴식의 가치를 증명하는 통계는 아니다.

1. **주도성은 자기 필요에 맞게 선택하는 태도다.** 탭·대기·드래그의 입력량을 주도성의 정의로 삼지 않는다. 스스로 선택한 멍때리기·귀환도 의미 있는 선택이다.
2. **몸 회복과 마음 환기는 다르다.** 이동·휴식에는 서로 다른 효과가 있고, 긴 휴식이 필요한 때와 이미 충분히 쉰 때를 구분한다.
3. **시야는 풍경과 화면의 열림으로 전달한다.** 넓은 장소만 찾아다니는 것이 항상 정답이 되지 않도록 이동 부담·남은 시간을 함께 고려한다.
4. **돈은 자원이며 휴식 가치의 점수가 아니다.** 현재 모델에서 지출 자체는 마음·만족감 보너스를 주지 않는다. 구매를 함정이나 도덕적인 실패로 규정하지 않는다.
5. **선택의 흔적을 남긴다.** 선택 직후에는 장면·개복치 반응, 마지막에는 기록으로 결과를 확인한다. 모든 확장을 MVP에 넣지는 않는다.
6. **결과를 조작하지 않는다.** 유료 휴식의 기록이 더 높아도 그대로 보여주고 장소·행동·몸 상태·체류를 함께 돌아본다. 총점·등급·방문 수 경쟁은 만들지 않는다.
7. **랜덤과 예측을 구분한다.** 장소 순서·사건·유료 행동의 비용 추첨은 시드 RNG를 사용한다. 몸·마음 계산은 같은 조건에서 결정적이며 예측은 RNG와 상태를 소비하지 않는다.

## 현재 기반과 이번 MVP

범위·완료 기준은 [mvp.md](mvp.md), 현재 진행과 임시 수치는 [day-logic.md](day-logic.md)를 따른다. 이 문서의 확장 기능은 현재 구현으로 간주하지 않는다. 초기 `ideation/candidate/` 문서는 과거 참고 자료다.

### 현재 구현 — 사람 검증은 별도

- 여행지 3개 중 선택해 09:00부터 21:00까지 여행한다. 여행지별 9장 덱에서 장소를 방문하며 실제 휴식·방문 횟수는 선택에 따라 달라진다.
- 이동 시간·다음 장소·시야를 예고하고 시간대별 빛을 보여준다. 도착하면 행동·다음 장소·귀환을 선택할 수 있다.
- 행동 후 30분을 적용하고 몸·마음 결과와 마음 환기를 유지한다. 이후 더 쉬기·이동·다른 행동·귀환을 고른다. 같은 행동 추가 휴식은 과제를 반복하지 않는다.
- 회복 포화와 과도한 체류 부담을 계산한다. 정오 이후 한 번의 식사는 별도 처리하고 사건·구매도 기록한다.
- 종료 사유는 시각 도달·자발적 귀환·통증 100·마음의 여유 0이다. 결과는 개별 쉼 막대·지출·타임라인·기록 상세를 보여준다.

```text
여행지 선택 → 이동·사건 → 도착 → 행동 / 이동 / 귀환
                                    ↓
                                30분 휴식
                                    ↓
                              몸·마음 결과 유지
                                    ↓
                    더 쉬기 / 다음 장소 / 다른 행동 / 귀환
                                    ↓
                            종료 → 자기 기록 돌아보기
```

기존의 고정 7턴·지출 보너스·무입력 자동 휴식·식사 휴식 행동·만족감 결과에서만 공개는 현재 기준에서 폐기했다. 만족감은 현재 휴식 결과에서도 마음 환기로 표시한다.

### 이번 MVP 작업 상태

| 순서 | 만들 것 | 성공 기준 |
| --- | --- | --- |
| 1 · 코드 작성 완료, 사람 확인 대기 | 현재·다음 풍경을 분리한 비교 화면, 휴식 직후 몸·마음·환기·지출 안내와 체류 부담 포함 설명 | 예상 효과·시간·비용·다음 풍경을 이해하고 선택 |
| 2 · 코드 작성 완료, 사람 확인 대기 | 통증은 자세·마음 여유는 유영으로 표현, 핵심 안내만 기본 표시하고 상세 설명은 접기 | 몸과 마음의 차이를 숫자와 함께 알아챔 |
| 3 · 미실시 | 실제 첫 플레이·휴대폰 검증과 필요한 수정 | 진행 중간값 3~5분, 추가 휴식 판단 이해, 터치로 끝까지 진행 |

현재 수치와 API·기록 형식을 유지한다. 행동별 고정 주도성은 MVP 모델의 한계다. ‘스마트폰은 나쁜 쉼, 돌아다니기는 좋은 쉼’이라는 보편적 결론으로 설명하지 않는다.

## MVP 이후 확장 순서

### 1. 두 갈래 다음 장소 선택 — 우선 확장

현재 장소에 머물기와 서로 다른 다음 장소 두 곳을 비교한다. 가까운 실내 쉼터와 조금 먼 열린 강변처럼 몸·마음·시간에 따라 매력이 달라지는 선택을 만든다. 방문 수나 열린 시야의 개수로 보상하지 않는다.

확장 시 덱의 후보 제시·선택하지 않은 카드 처리, 재방문 여부, 사건 배정과 개복치의 제안, 비의 시야 예고, 시간·잠금·예측, 경로 기록과 시뮬레이션을 함께 설계한다. 이 정책은 구현 전에 확정한다. 이번 MVP에는 다음 장소 한 곳의 예고를 유지한다.

검증은 선택 이유를 플레이어가 설명할 수 있는지, 몸이 지친 상황과 마음 환기가 필요한 상황에서 선택이 달라지는지, 한 경로가 모든 상황의 정답이 되지 않는지에 집중한다.

### 2. 쉬는 방식의 선택과 주도성 재설계 — 다음 확장

스마트폰·계획부터 세부 선택을 넣고 결과에 흔적을 남긴다. 예를 들어 스마트폰은 듣고 싶은 음악 고르기·친구에게 연락하기, 계획은 보고 싶은 곳 고르기·남은 일정 하나 덜어내기로 구성할 수 있다. 예시는 후보이며 현재 구현 사양이 아니다.

선택이 장면·다음 행동·기록에 어떤 차이를 만드는지 먼저 정하고, 필요하면 행동별 고정 주도성을 재설계한다. 버튼만 늘거나 동일한 정답이 반복되지 않게 한다. 조작 속도·정확도·횟수로 휴식 보상을 만들지 않는다. 새 산식·필드·효과와 밸런스 변경은 이 단계에서 별도 승인·검증한다.

### 3. 회상과 재플레이 — 후속 후보

- 그래프 전에 기억에 남은 쉼을 골라 주관적 기억과 실제 몸·마음·지출 기록을 함께 확인한다. 정답 맞히기로 만들지 않는다.
- 같은 장소 순서·사건 조건으로 다시 여행하고 선택의 차이를 비교한다. 경로 분기 도입 뒤에는 같은 시드만으로 사건 조건까지 같다고 단정하지 않고 재현 방식도 설계한다.
- 기본 선택의 재미와 결과 이해를 검증한 뒤 도입한다. 현재 MVP에는 기존 막대 상세 보기와 일반 다시 여행하기만 유지한다.

### 4. 콘텐츠·연출 — 선택적 후보

작은 바람 설정, 풍경 속 발견, 사건의 후속 반응, 포스터 스크롤 조립, 개복치 해체, 실제 하루 겹치기, 쉼 유형 분류, 스와이프, 사운드, 공유·이미지 저장은 후속 후보로 둔다. 발견·방문 개수 경쟁이나 휴식을 바쁘게 수행해야 하는 과제로 만들지 않는다.

제작자 실제 기록을 비교 자료로 쓸 경우 출처·수치화 기준을 별도로 정리하고 ‘한 사람의 하루이며 통계가 아니다’라는 설명을 붙인다. 현재 MVP에 없는 비교 데이터나 파일이 존재한다고 가정하지 않는다.

## 결과와 검증

결과의 중심은 **내가 어디서 어떻게 얼마나 쉬었고, 몸과 마음에 어떤 변화가 있었는가**다. 막대는 쉼의 마음 환기, 지출은 별도 점·선, 타임라인은 이동·식사·쉼·사건을 보여준다. 식사·구매는 유료·무료 휴식 평균에서 제외한다. 과도한 체류 부담은 마음의 전체 변화에 포함된 부분이며 중복 차감하지 않는다.

유료·무료 한쪽 기록이 없으면 비교를 만들지 않는다. 휴식이 없거나 조기 귀환했어도 남은 기록을 그대로 보여준다. 기록 개수는 고정하지 않는다.

- 자동 검증: 계산 경계·분할 휴식 동등성·예측 일치·진행·잠금·기록 호환, 전략 시뮬레이션, 빌드. 현재 합격 기준과 이전 실행 결과는 `day-logic.md`를 참조한다.
- 사람 검증: 첫 플레이 사용자 3명 이상, 여행지 선택부터 기록 진입까지 측정. 결과 감상 제외 중간값 3~5분, 3명 중 2명 이상이 필요한 추가 휴식과 불필요한 반복 체류를 구분하는 것이 목표다.
- 몸·마음 표현 이해, 선택에서 막힌 지점, 긴 휴식 이유, 체류 부담 이유, 돈·장소·행동에 대한 해석과 재미를 느낀 순간도 기록한다.
- 현재 사람 플레이 검증은 미실시다. 기존 시뮬레이션 시간 추정은 현재 UI의 실측 시간이 아니다. 재미·전달 성공은 자동 테스트 통과와 구분한다.

## 기술과 제출 순서

| 영역 | 현재 기준 |
| --- | --- |
| 앱 | Vite vanilla JS, GSAP 3, SVG + CSS |
| 결과 배경 | 현재 작업 트리에 `curtainsjs`·WebGL 코드가 있음. 문서 정리에서는 변경하지 않음 |
| 계산·진행 | `state.js`의 상수·순수 계산, `day.js`의 하루 진행, 방문·개별 쉼·식사·사건 기록 |
| 씬·결과 | 인트로·출발·턴·엔딩·결과, 결과 집계와 상세 설명 |
| 배포 | Vercel, `main` push 시 자동 배포 |
| 확인 | `npm test` / `npm run sim` / `npm run build`, 시드·디버그·결과 샘플 |

React·Tailwind·Three.js를 사용하지 않는다. Lenis·새 라이브러리 설치를 전제로 하지 않는다. 씬 전환의 타이머·리스너·애니메이션 정리, 즉시 입력 잠금, 정밀값 계산, 모바일 터치 규칙은 `AGENTS.md`와 `CLAUDE.md`를 따른다.

10/11~10/12에는 비교 화면 개선 → 상태 표현 → 사용자 검증·수정 → 빌드·배포 URL 휴대폰 확인 → 제출 순서로 진행한다. 각 단계는 확인 후 커밋한다. 시간이 부족하면 신규 연출보다 진행·선택 이해·결과 가독성·모바일 문제를 우선한다. 완료된 기본 루프를 다시 만드는 일정이나 포스터 단독 제출 전환을 현재 기준으로 두지 않는다.

비교 화면 개선과 개복치 상태 표현·짧은 안내는 코드 작성과 자동 검증(`npm test` 53개·빌드 통과)을 마쳤다. 자세·유영은 독립적으로 표시하고, 환기 점수와 세부 설명은 기본 접힌 `자세히`로 제공한다. 상태 표현 네 가지 조합·작은 화면 잘림·밤 가독성·설명 펼치기·움직임 줄이기와 실제 재미는 사람 확인이 남아 있다. 사용자 검증·배포 완료를 뜻하지 않는다. `journal.md`는 사람이 작성하고 수정하지 않는다.
