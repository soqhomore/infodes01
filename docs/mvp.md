## 4. 화면 흐름

```
intro ── 여행지 선택 ──▶ turn × 7 ──▶ ending ──▶ result
                           │
                           └─ 의지 0 또는 통증 100이 되는 즉시 ending
```

### 한 턴의 순서 (이 순서를 그대로 지킨다)

1. **이동**: 통증 += 이동 증가량(턴별). 이 시점에 장소 카드를 덱에서 **미리 뽑아 둔다** (아직 공개하지 않음).
2. **이벤트**: 이번 턴에 슬롯이 배정돼 있으면 발생 (§7). 효과 즉시 적용.
3. **엔딩 체크**
4. **장소 공개**: 카드 이름, 시야 등급, 실내 여부. `clip-path` 적용.
5. **쉴까?**
   - 지나친다 → 통증 +4, Δ의지 = −3 + 통증 패널티, 이 턴은 휴식 기록 없음 → 7로
   - 쉰다 → 6으로
6. **행동 선택과 실행**: 잠금 조건은 이 시점의 통증으로 판정
7. **결과 표시**: 통증·의지 변화량을 보여 준다 (만족감은 보여 주지 않는다)
8. **엔딩 체크** → 다음 턴

> **MVP 가정:** 기획서에 건너뛴 턴의 의지 변화가 정의돼 있지 않아 "−3 + 통증 패널티"로 둔다. 플레이 후 조정.

## 5. 수치 (`src/state.js`)

### 초기값

| 스탯 | 초기값 | 범위 | 표시 |
| --- | --- | --- | --- |
| 통증 `pain` | 15 | 0~100 | 보임 |
| 의지 `drive` | 45 | 0~100 | 보임 |
| 예산 `budget` | 8000 | 0~ | 보임 (¥, 천 단위 콤마) |
| 만족감 `satisfaction` | — | 휴식당 0~10 | 숨김 |

### 이동 시 통증 증가

| 턴 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 증가량 | 8 | 9 | 11 | 12 | 14 | 16 | 18 |

지나치기 추가 통증: **+4**

### 휴식 시 통증 회복

```
실제 회복량 = 행동 회복량 × 효율
```

효율은 **휴식 시작 시점의 통증**으로 판정한다.

| 휴식 시작 통증 | 효율 |
| --- | --- |
| 0~39 | 1.0 |
| 40~69 | 0.75 |
| 70~100 | 0.5 |

### 의지

```
Δ의지 = −3 + 주도성 + 시야 보너스 + 돈 보너스 + 통증 패널티
```

- 돈 보너스: 이번 휴식에 지출이 있으면 **+1**, 없으면 0. 금액과 무관.
- 통증 패널티: **휴식 종료 후 통증**으로 판정.

| 휴식 후 통증 | 패널티 |
| --- | --- |
| 0~39 | 0 |
| 40~59 | −3 |
| 60~79 | −6 |
| 80~100 | −10 |

### 숨은 만족감

```
만족감 = 3 + 주도성/2 + 시야 보너스/2 + 돈 보너스 + 통증 패널티/2
→ Math.round → 0~10으로 자르기
```

### 시야 등급

| 등급 | 시야 보너스 | `clip-path` 폭 |
| --- | --- | --- |
| narrow | +1 | 40% |
| mid | +3 | 70% |
| wide | +7 | 100% |

## 6. 행동

| id | 이름 | 주도성 | 회복량 | 지출 | 조작 | 사용 조건 |
| --- | --- | --- | --- | --- | --- | --- |
| `spacing` | 멍때리기 | 1 | 14 | — | 6초 무입력 (아래) | 없음 |
| `phone` | 스마트폰 | 0 | 12 | — | 탭 | 없음 |
| `dessert` | 디저트 | 2 | 9 | ¥600~1,200 | 탭 | 예산 ≥ 1,200 |
| `meal` | 식사 | 3 | 11 | ¥900~1,800 | 탭 | 예산 ≥ 1,800 |
| `chat` | 잡담 | 4 | 10 | — | 탭 | 통증 < 85 |
| `plan` | 계획 짜기 | 6 | 5 | — | 탭 (MVP) | 통증 < 80 |
| `wander` | 돌아다니기 | 7 | 3 | — | 개복치 원을 드래그해 화면 끝까지 이동 | 통증 < 65, 실외 카드 |

- 지출 금액: 범위 안에서 RNG로 100엔 단위.
- 잠긴 행동은 회색으로 **보이게** 두고, 왜 잠겼는지 한 줄 표시 ("발이 너무 아프다", "실내라 돌아다닐 수 없다", "돈이 부족하다").
- **통증 80 이상**이면 "지나친다" 버튼도 잠기고 "몸이 대신 정했다." 문구를 띄운다.

### 멍때리기 무입력

- 행동 선택지가 전부 나타난 순간부터 타이머 시작.
- 3초부터 화면이 서서히 흐려진다 (opacity 또는 blur).
- 6초가 되면 `spacing` 자동 실행, 문구: **"아무것도 안 했다. 개복치도."**
- 포인터 이동, 터치, 키 입력이 있으면 타이머를 0으로 리셋하고 흐림도 되돌린다.
- 멍때리기를 버튼으로 직접 고를 수는 없다. 아무것도 안 해야만 실행된다.
- 화면을 떠날 때 타이머를 반드시 해제한다.

## 7. 돌발 이벤트 (세션 패턴)

게임 시작 시 RNG로 이벤트 턴을 미리 정한다. 세 슬롯은 **서로 다른 턴**이어야 한다.

| 슬롯 | 배정 턴 | 후보 |
| --- | --- | --- |
| 유혹 | 3~5 | 한정 디저트 |
| 부정 | 2~6 | 발을 삐끗, 비 |
| 긍정 | 2~6 | 축제 발견, 개복치의 제안, 벤치 발견 |

해당 턴이 오면 후보 중 **조건을 만족하는 것**에서 RNG로 하나 고른다. 하나도 없으면 그 턴은 이벤트 없이 지나간다. 같은 이벤트는 한 판에 한 번만.

| 이벤트 | 조건 | 선택지 → 효과 |
| --- | --- | --- |
| 한정 디저트 | 없음 | 산다 → 예산 −2,500, 의지 +3, 통증 −10 / 지나친다 → 변화 없음. 예산 < 2,500이면 "산다"를 비활성으로 **보여 준다** |
| 발을 삐끗 | 통증 ≥ 30 | (선택 없음) 통증 +10, 의지 −5 |
| 비 | 턴 ≤ 4 | (선택 없음) **다음 턴** 시야 한 단계 하락 (narrow 아래로는 안 내려감) |
| 축제 발견 | 이번 턴 카드가 실외 | 구경한다 → 이번 턴 시야를 wide로, 의지 +4 / 지나친다 → 의지 −2 |
| 개복치의 제안 | 턴 ≥ 3 | 따라간다 → 의지 +4, 다음 턴 카드를 남은 덱에서 시야가 가장 넓은 카드로 교체 / 거절한다 → 의지 −2 |
| 벤치 발견 | 통증 ≥ 50 | (선택 없음) 통증 −8 |

- 한정 디저트 지출은 휴식이 아니므로 결과 막대에 들어가지 않는다. 총 지출에만 더한다.
- 이벤트 효과 직후에도 엔딩 체크를 한다 (발을 삐끗으로 통증 100 가능).

| 여행지 | narrow (실내) | mid | wide (실외) |
| --- | --- | --- | --- |
| 도시 | 쇼핑몰 내부, 백화점 휴게 의자, 창 없는 카페, 지하 통로, 역 대합실 | 창가 카페(실내), 골목 벤치, 공원 벤치 | 강변 |
| 마을 | 작은 상점, 창 없는 카페, 역 대합실 | 창가 카페(실내), 골목, 신사 경내, 공원 벤치 | 강변, 언덕 위 |
| 바닷가 | 기념품점, 창 없는 카페 | 창가 카페(실내), 골목, 방파제 계단 | 해변, 등대 앞, 해안 산책로, 바다 보이는 테라스 |

```js

```

## 10. 엔딩과 결과 화면

### 엔딩 판정

| 조건 | 엔딩 | 한 줄 |
| --- | --- | --- |
| 의지 0 | 조기 귀국 | 개복치는 숙소로 돌아가 버렸다. |
| 통증 100 | 발이 먼저 끝냈다 | 개복치는 더 걷지 못하고 주저앉았다. |
| 완주, 의지 ≥ 70 | 좋은 하루 | 개복치가 팔딱거린다. |
| 완주, 의지 40~69 | 무난한 하루 | 개복치는 평온하다. |
| 완주, 의지 < 40 | 길었던 하루 | 개복치는 지쳤다. |

점수나 등급 표시는 없다. 엔딩 아래 [결과 보기] 버튼.

### 결과 화면 (정적 SVG)

1. **만족감 막대 7개**: 턴 순서대로. 지출 있음 = 초록, 없음 = 회색. 초록은 지출이 클수록 진하게 (`opacity = 0.35 + 0.65 × 지출/1800`). 건너뛴 턴은 빈 칸에 "지나침" 라벨. 조기 엔딩이면 남은 턴은 비워 둔다.
2. **금액 선**: 막대 위쪽에 지출액을 점으로 찍고 선으로 잇는다. 막대 높이와 따로 노는 것이 보여야 한다.
3. **(쉬우면) 통증 점선과 의지 면**: 턴별 휴식 후 통증·의지를 겹쳐 그린다.
4. **평균 두 숫자**: "돈을 쓴 휴식 평균 ○.○ / 돈을 안 쓴 휴식 평균 ○.○"
5. **어긋날 때 문구**

| 경우 | 문구 |
| --- | --- |
| 돈 쓴 평균 ≤ 안 쓴 평균 | 돈을 쓴 휴식이 더 좋았던 건 아니었다. |
| 돈 쓴 평균 > 안 쓴 평균 | 이번에는 돈을 쓴 휴식이 더 좋았다. 그때 어디에 있었는지 확인해 보자. |
| 한쪽 기록이 없음 | 비교할 짝이 없다. 대신 아래 세 휴식을 보자. |

   그 아래 작게: **"만족감 계산에는 '돈을 썼는지'만 +1로 들어갔다. 금액은 들어가지 않았다."**

6. **세 휴식 강조**: 막대 위에 라벨

| 라벨 | 기준 |
| --- | --- |
| 몸을 가장 쉬게 한 휴식 | 실제 통증 회복량 최대 |
| 다시 걷게 한 휴식 | Δ의지 최대 |
| 가장 비쌌던 휴식 | 지출 최대 (지출 없으면 생략) |

   동점이면 나중 턴. "다시 걷게 한 휴식"과 "가장 비쌌던 휴식"이 다른 막대면 "가장 비쌌던 휴식이 나를 다시 걷게 한 건 아니었다.", 같은 막대면 "이번에는 가장 비쌌던 휴식이 가장 좋았다. 그때 시야는 ○○이었다."

7. 각 막대 아래에 행동 이름과 장소 이름을 작은 글씨로.
8. [다시 하기] 버튼.

### 휴식 기록 형태 (턴마다 하나)

```js
{
  turn: 3,
  skipped: false,
  card: { name: '창가 카페', view: 'mid', indoor: true },
  action: 'dessert',
  spend: 900,
  painBefore: 42, painAfter: 35, painRecovered: 7,
  driveBefore: 48, driveAfter: 51, driveDelta: 3,
  satisfaction: 6
}
```

## 11. 시뮬레이션 (`npm run sim`)

UI와 분리된 순수 함수(`state.js`)를 Node로 돌려 수치를 검증한다. **UI보다 먼저 만든다.**

- 이벤트 없이, 카드는 각 여행지 덱에서 시드 고정으로 뽑는다.
- 각 경로를 시드 10개로 돌려 평균을 낸다.
- 행동이 잠기면 멍때리기로 대체한다.

| 경로 | 여행지 | 규칙 | 기획서 값 (의지 / 통증 / 만족감) |
| --- | --- | --- | --- |
| 돌아다니기 올인 | 바닷가 | 가능하면 wander | 80 / 76 / 6.9 |
| 영리한 혼합 | 마을 | 통증 ≥ 45면 spacing, 아니면 wander(실내면 plan) | 77 / 53 / 6.6 |
| 계획 위주 | 마을 | 가능하면 plan | 76 / 73 / 6.4 |
| 영리한 혼합 | 도시 | 위와 동일 | 68 / 39 / 6.0 |
| 돈 쓰기 | 도시 | meal → 예산 부족 시 dessert → 그것도 안 되면 spacing | 60 / 33 / 6.0 |
| 스마트폰만 | 도시 | 항상 phone | 43 / 19 / 4.6 |

±5 이상 차이 나는 경로가 있으면 **수치를 고치지 말고** 표로 보고한다. 기획서 시뮬레이션의 경로 규칙이 정확히 기록돼 있지 않아 차이가 날 수 있다.

## 13. 구현 순서

한 단계 = 한 번의 요청. 단계가 끝날 때마다 확인하고 커밋한다.

| 단계 | 할 일 | 확인 |
| --- | --- | --- |
| 0 | Vite vanilla 프로젝트, GSAP 설치, `.gitignore`(`.DS_Store` 포함), git, GitHub, Vercel 연결. `<title>` 변경, `word-break: keep-all`, `100dvh` | 빈 페이지가 Vercel URL에서 열린다 |

| 3 | 행동 조작 분기: 멍때리기 무입력, 돌아다니기 드래그, 잠금 표시 | 6초 방치 시 자동 실행, 다음 턴에 타이머가 새지 않는다 |

| 6 | 결과 화면 + `?jump=result` | fake-run과 실제 플레이 둘 다 막대가 맞게 그려진다 |
| 7 | 휴대폰 실기 테스트, 터치 문제 수정 (`touch-action`, `user-select`, `overscroll-behavior`) | iPhone Safari에서 드래그 중 화면이 안 밀린다 |
