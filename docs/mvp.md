# MVP 명세 — 개복치 휴식 시뮬레이터

2026-10-11 갱신 · 제출 마감: 2026-10-12(월) 23:59

## 목적과 문서 기준

정보디자인 포스터 「내 휴식은 충분히 가치 있었을까?」를 3~5분의 하루 여행으로 옮긴다. 이번 MVP는 **내 상태에 맞게 휴식·이동을 선택하고, 몸의 회복과 마음의 환기를 구분하며, 자기 기록을 돌아볼 수 있는지** 검증한다.

메시지는 휴식의 가치가 금액보다 주도성과 시야의 넓이에 달려 있다는 것이다. 게임의 기록은 설계된 규칙의 결과이며 실제 휴식의 가치를 증명하는 통계가 아니다. 특정 행동이나 많은 방문을 정답으로 만들지 않는다.

- 이 문서: 이번 MVP의 범위·작업 순서·완료 기준.
- [day-logic.md](day-logic.md): 현재 진행·계산·임시 수치의 기준. 충돌하면 이 문서를 우선한다.
- [plan-v2.md](plan-v2.md): 본 계획과 이후 확장. 여기만 있는 기능은 먼저 구현하지 않는다.
- 이전 7턴 명세를 대체한다. 현재 진행은 고정 7턴이나 고정 7번의 휴식이 아니다.

## 현재 구현과 다음 작업

아래 구현 표시는 코드가 있는 상태를 뜻한다. 실제 재미·직관성·플레이 시간·휴대폰 조작은 사람 검증이 남아 있다.

| 영역 | 현재 구현 |
| --- | --- |
| 하루 | 여행지 3개, 09:00 출발·21:00 귀환 시각, 시간대별 빛 |
| 장소 | 여행지별 9장 덱, 다음 장소·시야·이동 시간 예고, 시야에 따른 화면 폭 |
| 휴식 | 행동 선택 후 30분 적용, 결과 유지, 같은 행동 추가 휴식·다른 행동·이동·귀환 |
| 판단 | 추가 30분의 회복·마음 변화·종료 시각·비용 범위와 다음 장소 정보 비교 |
| 몸과 마음 | 통증·마음의 여유·예산 표시, 회복 포화와 과도한 체류 부담, 휴식 결과에 마음 환기 표시 |
| 식사·사건 | 정오 이후 한 번의 별도 식사, 이동 중 사건, 구매 기록 |
| 결과 | 개별 쉼 막대와 지출, 하루 타임라인, 기록 상세·강조 항목, 유료·무료 휴식 평균 |
| 기술 검증 | 순수 계산 함수, 시드 RNG, 테스트·시뮬레이션, 결과 샘플 |

### 이번 MVP에 만들 것 — 예정

1. **휴식·이동 비교 화면 개선.** 현재 장소에 더 머물기와 다음 장소로 이동하기를 같은 비중의 장면·선택 영역으로 보여준다. 추가 휴식에는 예상 몸·마음 변화·종료 시각·비용 범위, 이동에는 다음 장소·시야·이동 시간을 표시한다. 다른 행동·귀환과 잠금 이유를 유지한다. 예측은 기존 함수와 데이터를 사용하며 정답 선택을 강조하지 않는다.
2. **간단한 개복치 상태 표현.** 기존 통증은 자세, 마음의 여유는 움직임으로 구분한다. 몸은 회복됐지만 마음은 답답한 상태도 표현할 수 있어야 한다. 숫자와 설명을 유지한다. 새 스탯·보상·행동 효과는 추가하지 않는다.
3. **기존 결과의 이해도 개선.** 몸 회복·마음의 여유 변화·마음 환기·지출의 의미를 구분한다. 막대를 눌러 그 쉼의 장소·행동·시간·효과를 돌아보는 기존 기능을 활용하고 안내를 정리한다. 별도의 회상 선택 화면은 추가하지 않는다.

위 항목은 이번 문서 정리로 구현된 것이 아니다. 게임 수치·행동별 주도성은 유지한다.

## 현재 플레이 흐름

```text
여행지 선택 → 출발 → 이동·사건 → 장소 도착
                                  ↓
                      행동 선택 / 다음 장소 / 귀환
                          ↓
                    행동 인터랙션 → 30분 휴식
                          ↓
                    몸·마음 결과를 읽는다
                          ↓
          30분 더 쉬기 / 다음 장소 / 다른 행동 / 귀환
                          ↓
                 종료 → 하루 기록 돌아보기
```

- 화면을 읽는 실제 시간은 게임 시각을 소비하지 않는다. 무입력으로 자동 휴식하지 않는다.
- 멍때리기는 직접 선택한다. 같은 행동의 추가 휴식은 과제를 반복하지 않고 짧은 연출로 진행한다.
- 취소는 시간·수치·지출을 바꾸지 않는다. 넘기기는 표시된 휴식 시간을 그대로 적용한다.
- 정오 이후 첫 선택 전에 한 번 식사한다. 휴식 중 정오가 되면 결과를 읽은 뒤 식사 또는 귀환을 선택하고, 식사 후 휴식·이동 판단으로 돌아온다. 식사는 휴식 회복·만족감 계산과 분리한다.
- 종료 사유는 시각 도달·자발적 귀환·통증 100·마음의 여유 0이다. 통증 80 이상이면 이동이 잠기지만 휴식·귀환은 가능하다.
- 장소 덱을 다 써도 남은 시간에 머물 수 있다. 방문 수는 점수나 성공 조건이 아니다.

### 행동과 기록

현재 휴식 행동은 멍때리기·스마트폰·디저트·잡담·계획 짜기·돌아다니기 6개다. 식사는 별도 선택이다. 잡담·계획은 짧은 선택, 돌아다니기는 드래그, 나머지는 선택 또는 짧은 연출로 진행한다. 잠금 조건과 모든 수치는 `state.js`를 기준으로 한다.

행동별 주도성은 현재 고정값이다. 이는 MVP 계산 모델의 한계로 기록한다. 조작량이 곧 주도성이라는 결론을 내리지 않으며, 행동 안에서 자기 필요를 선택하게 하는 재설계는 본 계획으로 미룬다.

방문과 개별 쉼은 별도 ID로 연결한다. 같은 장소에서 여러 번 쉬면 각각 기록하며, 결과 막대 수는 실제 휴식 횟수에 따라 달라진다. 식사·구매는 별도 기록이고 휴식 평균에서 제외한다. 기존 기록 형식을 유지하며 예전 샘플도 읽는다. 새 API·기록 필드는 이번 MVP 개선의 요구 사항이 아니다.

## 본 계획으로 미루는 것

| 우선순위 | 기능 | 미루는 이유 |
| --- | --- | --- |
| 우선 확장 | 두 갈래 다음 장소 선택 | 덱·사건·예측·시뮬레이션과 이동 균형 변경이 필요 |
| 다음 확장 | 스마트폰·계획의 세부 선택, 선택의 흔적, 주도성 재설계 | 선택 의미와 효과·산식을 함께 설계해야 함 |
| 후속 후보 | 기억에 남은 쉼 먼저 선택, 같은 하루 재플레이·비교 | 기본 선택의 재미 검증 이후 추가 |
| 후속 후보 | 작은 바람·풍경 발견·사건 후속 반응 | 새 목표·콘텐츠·기록 범위를 늘림 |
| 선택적 연출 | 스와이프·포스터 스크롤 조립·개복치 해체·실제 하루 겹치기 | MVP 검증에 필수 아님 |
| 선택적 확장 | 사운드·공유·이미지 저장·이름 입력·쉼의 유형 분류 | 이번 완료 조건에서 제외 |

이미 작업 중인 배경 연출을 이 목록을 이유로 삭제하거나 확장하지 않는다. 새 라이브러리는 설치하지 않는다.

## 단계와 확인 방법

한 번에 한 단계만 진행한다. 각 단계에서 빌드를 확인하고 해당 변경만 커밋한다.

| 단계 | 작업 | 사람이 확인할 항목 |
| --- | --- | --- |
| 1 · 예정 | 휴식·이동 비교 화면과 기존 결과 안내 정리 | 두 선택을 비교할 수 있는가, 과도한 체류 부담을 중복 차감으로 오해하지 않는가 |
| 2 · 예정 | 개복치 몸·마음 상태 표현 | 자세와 움직임의 의미를 구분하는가, 숫자와 표현이 맞는가 |
| 3 · 미실시 | 첫 플레이 사용자 검증·필요한 수정 | 시간·막힌 선택·긴 휴식 이유·체류 부담 이해·재미 |
| 4 · 예정 | 배포 URL의 휴대폰 확인·제출 | 터치로 끝까지 진행하고 기록을 볼 수 있는가 |

### MVP 완료 체크리스트

- [ ] 휴대폰 배포 URL에서 시작부터 하루 기록까지 조작할 수 있다.
- [ ] 추가 휴식·이동의 정보를 비교하고 잠금 이유를 알 수 있다.
- [ ] 몸 회복과 마음 환기의 차이를 숫자·개복치 표현·기록에서 확인할 수 있다.
- [ ] 실제 쉼마다 결과 막대가 생기고, 반복 체류·식사·구매 기록을 구분할 수 있다.
- [ ] 첫 플레이 사용자 3명 이상을 안내 없이 관찰했다. 여행지 선택부터 하루 기록 진입까지의 중간값이 3~5분이다. 결과 감상 시간은 제외한다.
- [ ] 3명 중 2명 이상이 필요한 추가 휴식과 불필요한 반복 체류를 구분한다.
- [ ] 몸·마음 표현의 이해, 선택에서 막힌 지점, 지출과 휴식 가치에 대한 해석, 재미를 느낀 순간을 기록했다. 플레이에 문제가 있으면 수정 후 다시 확인한다.
- [ ] `npm test`, `npm run sim`, `npm run build` 확인. 시뮬레이션 합격 기준과 이전 결과는 `day-logic.md`를 따른다.

자동 검증 통과는 체감 재미·전달 성공·실제 3~5분 달성을 뜻하지 않는다. 사람이 작성하는 `journal.md`는 수정하지 않는다.

## 개발·검증 도구

Vite vanilla JS, GSAP 3, SVG + CSS, Vercel을 사용한다. 현재 작업 트리에는 결과 배경용 `curtainsjs`와 WebGL 코드도 있으며 이번 문서 작업의 변경 대상은 아니다. 자세한 개발 규칙은 `AGENTS.md`와 `CLAUDE.md`를 따른다.

- `npm run dev`: 로컬 플레이 확인.
- `npm test`: 계산·진행·씬 동작 검증.
- `npm run sim`: 순수 로직으로 전략별 수치·종료·시간 추정 검증.
- `npm run build`: 배포용 번들 생성 확인.
- `?seed=123`: 같은 시드로 재현. `?debug=1`: 상태 확인.
- `?jump=result`: `src/data/fake-day.js`의 하루 샘플로 결과 확인. 예전 샘플 호환도 유지한다.
